## 概览

QeEdu 可以按 Community、Cloud、Education 三层规划，但比赛阶段要诚实表达当前能力和未来路线。

## 当前阶段

当前重点是：

- 官网讲清产品定位和商业模式。
- Cloud 提供可体验的核心产品。
- Docs 支撑部署、试点、数据安全和开发说明。
- GitHub 保留社区版代码入口。

## Community

Community 适合开源共建、自部署体验和开发者学习。短期目标是让用户能按文档启动项目，并提交 Issue 或场景模板。

## Cloud

Cloud 适合快速试用、演示和轻量协作。它是商业化线索入口，但不应承接高敏校务数据。

## Education

Education 面向私有化部署、校本知识库初始化、场景模板定制、权限审计和培训服务。它是面向高校的主要交付形态。

## 优先级

建议优先级：

1. 打磨 Cloud 演示体验。
2. 完善社区版部署文档。
3. 沉淀试点模板和知识库初始化方法。
4. 再包装教育版交付和报价。
